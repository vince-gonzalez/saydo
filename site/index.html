F-Keys · WARRANT

Prove a tool behaves as it says.

Signing and provenance prove a tool's code is what the publisher released. They do not prove the tool behaves as its description promises. WARRANT is the layer that tests that second claim: a signed contract per tool, a harness that checks the tool against it, and a hash-chained receipt anyone verifies without trusting us.

Working proof of concept   Name provisional. Declarations are drafts; receipts are unsigned.

The gap

Tool poisoning, capability rug-pulls, and silent behavioral drift are one problem: the distance between what a tool declares and what it does. The provenance standards say so themselves.

TBOM states it “cannot verify tool behavior matches descriptions.” CTMS states it verifies that a tool's claims have not changed, not that they are true.

WARRANT does not replace those standards. It extends them: the declaration binds to the same tool-definition digests a Tool Bill of Materials records, and attaches to one without changing its schema.

Four layers

Declaration A signed, machine-readable contract per tool: the behavior it is permitted to show — no network, writes only here, deterministic, returns errors as values. Ten invariant types in the current draft.
Conformance A harness exercises the tool under observation — valid calls, adversarial input, egress and filesystem monitoring — and reports pass, fail, or not-covered per invariant. It cannot prove an invariant it did not exercise, and it says so rather than passing it.
Receipt Every run emits a hash-chained record: one row per verdict, chained by row_hash = sha256(prev + row). Edit one row and the chain breaks at it. An auditor re-verifies it in a browser, no account, no request to us.
Trust mark A “Warranted” badge served from the registry, linking to the full findings rather than a bare grade, with expiry and revocation. Not built yet.

Run it

Install one of the covered servers, then put it under warrant. The command captures the tool definitions, exercises the server, and writes a receipt. 

# one MCP server, one warrant, one receipt
warrant verify certivl

  certivl   CONFORMANT
  tally     {'pass': 9}
  receipt   receipts/certivl.receipt.jsonl
  head      353e94cd497115aa49e10ab76874ab7bd9645feda12322a66785f0a961d3a19a

A harness that only ever passes is worth nothing, so it ships with a server built to fail. warrant selfcheck runs it and requires the harness to catch every violation: 

warrant selfcheck

  malserver   NOT CONFORMANT   {'pass': 1, 'fail': 5}
    network.none      FAIL  egress: fetch_quote->socket.connect
    writes.none       FAIL  write outside scope
    subprocess.none   FAIL  run_helper spawned a child
    roll.deterministic FAIL same input, different output
    errors.are-values FAIL  raised instead of returning an error
  seeded server caught: YES

Check it without us

The receipt is the point. Anyone recomputes the chain from its genesis anchor in a browser page that makes no network request and holds no account. A changed verdict, a deleted row, or a receipt re-anchored to a false head are each rejected and named. The verifier reuses the hash-chain engine from THE RECORD, unchanged.

What a green receipt does and does not say

It says: this run's observed behavior stayed inside the declared envelope, and the record has not been altered since.

It does not say: the tool is safe, correct, or good. The monitor watches the language runtime, not the kernel — it catches drift, accidents, and false declarations made by ordinary code, and it is not a sandbox. The receipt states that limit in its own text.

Built on, and citing

The provenance layer this extends is open and unratified, and the right place to contribute rather than compete: the Tool Bill of Materials (Jason M. Lovell) and the Canonical Tool Manifest Specification (George Kanellopoulos). The behavioral-conformance seam — continuous conformance to a declared contract, with independently verifiable receipts — was surveyed open on 2026-08-29 against the gateway, ledger, and badge tools then shipping. The survey is dated because the space moves weekly.

What is free

The declaration schema, the reference harness, the CLI, and the browser verifier are open under Apache 2.0. The current proof of concept was dogfooded on five live F-Keys MCP servers. Nothing here is paid, and nothing here is published as a claim of conformance.
